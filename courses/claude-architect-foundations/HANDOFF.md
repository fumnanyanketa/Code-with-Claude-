## 1. What exists right now (two separate things)

### A) The `course-builder` skill — the reusable engine
A Claude skill that turns transcripts into a polished, beginner-friendly HTML
course. It lives at:

```
.claude/skills/course-builder/
├── SKILL.md                      # the pipeline: ingest → sequence → write → render
├── references/
│   ├── pedagogy.md               # WHY the structure is what it is (read first)
│   ├── lesson-template.md        # the exact per-lesson skeleton the renderer needs
│   └── course-structure.md       # on-disk layout, course.json, PROGRESS.md
└── scripts/
    ├── build_course.py           # orchestrator: renders all lessons + landing page
    ├── build_lesson.py           # one Markdown lesson → one styled HTML page
    └── build_index.py            # the landing page
```

This skill is generic and config-driven — it can build ANY course, not just this
one. It was also packaged as an installable `course-builder.skill` file.

## 3. How the build works (so you can regenerate after edits)

Requirements: Python 3, and the `markdown` + `pygments` packages (the orchestrator
auto-installs them if missing).

```bash
python3 .claude/skills/course-builder/scripts/build_course.py \
        courses/claude-architect-foundations
```

This reads `course.json` + every `lessons/*/*.md`, renders `lessons-html/`, rebuilds
the landing page, and writes the root `index.html` redirect. Open
`courses/claude-architect-foundations/lessons-html/index.html` to view.

**Contract the renderer depends on** (full detail in the skill's
`references/lesson-template.md`):
- Each lesson's first line: `# Module N · Lesson M: Title` (middle dot `·` = U+00B7).
- A meta blockquote right after it (Course / Module / Speaker / Source / Estimated time).
- A `## In one sentence` paragraph (becomes the hero lead).
- A heading containing "Capstone" (becomes the project banner).
- Callouts are blockquotes starting with an emoji: 🔑 key · 💡 tip · ✅ do · ❌ pitfall · 🎯 goal · 🛠 project.
- `course.json` `modules` map controls the landing-page module names/blurbs; Module 0
  is treated as an optional pre-flight and excluded from the headline counts.

## 4. The course's design at a glance (keep this consistent when you enrich)

- **8 modules, 28 lessons**, re-sequenced from exam-guide order into a dependency-
  ordered learning path (prompting/structured output pulled forward to Module 2;
  Domain 1 split into foundational M1 vs advanced M3). See `COURSE_OUTLINE.md`.
- **North-star project "Atlas Support":** one multi-agent system that grows across
  the course, ending as a support agent that escalates to a human. Every capstone
  adds a component. Keep new lessons feeding this.
- **Per-lesson pedagogy:** in-one-sentence, plain-language glossary, "why it
  matters", objectives, numbered Parts with the speaker's real quotes, key
  takeaways, common pitfalls, a hands-on capstone with milestones, a cheat sheet,
  and "how this connects." The bar: a total beginner can read it and finish the
  capstone unaided.
- **Recurring theme to preserve:** "the docs, the AI, and the exam guide are often
  wrong — build it and verify." Several lessons teach verify-it-yourself moments.

## 5. Enrichment plan — make it current AND original (the point of this handoff)

Two goals: (1) **accuracy** — the source video may be out of date; (2)
**originality** — right now it closely tracks one person's course, so make it a
genuinely distinct work before publishing.

### 5a. Verify/update against official, current sources
Have the local session search the web and reconcile each item, updating lessons
where reality differs (and teaching the difference where useful):

- **The official Anthropic certification page + exam guide** for "Claude Certified
  Architect" / "Foundations." Confirm: the real domain names + weights, question
  count, passing score, time limit, and eligibility. Our current exam facts came
  from the video (code "CCA-F", 60 Q, 720/72%, 17 wrong, 120 min) and are
  explicitly described in-video as unofficial — verify them.
- **Current Claude model names / IDs / pricing.** Lessons use illustrative model
  names that drift; update to the current lineup and note that names change.
- **Claude Agent SDK (Python + TypeScript) current API.** The course flags places
  where the Python SDK lagged TS (fork sessions, agent-definition fields,
  `tool_choice`). Re-verify — some gaps may be closed now.
- **MCP spec** (tools vs resources vs prompts) — confirm still current.
- **Claude Code** settings, permission rules/modes, sandboxing, built-in tools,
  and GitHub Actions — verify against current docs.
- **Anthropic guides worth citing** as first-principles companions: "Building
  Effective Agents", the prompt-engineering docs, the Message Batches API docs.

For each lesson, update the illustrative code to today's SDK, and fix anything the
docs now contradict. Keep the "verify it yourself" framing.

### 5b. Make it original (not a copy)
- Replace reconstructed examples with **your own** scenarios and datasets; write
  **fresh capstones** where they're too close to the source labs.
- Add net-new value the video doesn't have: **original practice questions** per
  module, a **mock exam**, a consolidated **glossary page**, and your own
  diagrams.
- Rewrite any passage that tracks the source too closely in your own words and
  structure. (It's already a paraphrase, but push it further.)
- **Attribution + disclaimer:** add a top-level `README.md` that (a) credits Andrew
  Brown / ExamPro as inspiration, (b) links people to buy the official ExamPro
  course and to Anthropic's official certification, (c) states clearly this is an
  independent personal-study reconstruction, not affiliated with or endorsed by
  Anthropic or ExamPro. Keep the existing footer disclaimer too.
- **Remove the transcript links** in each lesson's meta `Source:` line (they point
  at the gitignored transcript) — repoint them to the official docs or drop the URL.
- Consider a `LICENSE` that reflects personal/educational, non-commercial intent.

### How to edit + re-render
Edit the Markdown in `lessons/`, then re-run the build command in §3. To add a new
lesson: create `lessons/module-N-slug/NN-slug.md` following the template, add its
module to `course.json` if new, and rebuild. To reorder, change the `NN` global
numbers (they drive ordering and prev/next).

## 6. Publishing (after enrichment) — the new public repo

You said you'll create the public repo yourself (the hosted GitHub app here can't
create repos — that's why we're handing off). Steps:

1. On github.com create a **public** repo, e.g. `claude-certified-architect-foundations`,
   empty (no README).
2. Locally, make the course its own repo root so GitHub Pages serves it cleanly:
   ```bash
   cd courses/claude-architect-foundations
   git init && git add . && git commit -m "Initial: CCA-F self-paced course"
   git branch -M main
   git remote add origin https://github.com/<you>/claude-certified-architect-foundations.git
   git push -u origin main
   ```
   (Make sure `transcripts/` stays out — add a `.gitignore` with `transcripts/`.)
3. Enable **GitHub Pages**: repo Settings → Pages → Source = "Deploy from a branch"
   → `main` / root. The root `index.html` redirects to `lessons-html/index.html`,
   so the site lands correctly.
4. Your URL will be roughly:
   `https://<you>.github.io/claude-certified-architect-foundations/`
   (first deploy takes a minute or two).

This new repo is completely independent of `Code-with-Claude-` and its default
branch — no conflict.
